### ТЗ-2. Тема приложения поверх темы-файла: `extends` молчит

**Класс:** B (предупреждение). **Касается:** INV-THM-2, INV-THM-4, §14
(`theme-extends-unresolved`), §4.3 п.3. **Roadmap:** «Долги вне очереди».

**Решено на `main`, не выпущено:** блок темы приложения встаёт в слое `themes` после
файлов тем, раньше идущих в `names`, и на `<html data-theme="ocean">` больше не
проигрывает `:root` светлой; путь «своя тема поверх темы-файла» — `define` с `tokensRef` —
описан в `docs/{ru,en}/themes-and-tokens.md` («Перекрасить тему провайдера»).

**Что ожидает потребитель.**

- Портал, `src/content/ru/docs/theming.md:150-176`: «Своя тема может быть частью конфига, и
  тогда её значения проходят ту же резолюцию, что и встроенные» — `define: { ocean: {
  extends: 'dark', selector: '[data-theme="ocean"]', tokens: { 'gr-primary': '#4fd1e0',
  'gr-bg': '#062b32' } } }`.
- `docs/ru/themes-and-tokens.md` — «`extends` наследует значения провайдерской темы (только
  структурные: тема из файла непрозрачна, и отчёт скажет `theme-extends-unresolved`)»;
  `docs/ru/troubleshooting.md`.

**Что делает код.** Предупреждение выдаётся, только если у базы нет ни одного структурного
токена: `core/resolveThemes.ts` (`Object.keys(baseTokens).length === 0`). У темы-файла ядра
структурные токены есть от компонентов селекции, поэтому при `components: 'all'`
предупреждения нет, а `ocean` наследует 63 покомпонентных токена (`--gr-button-*`,
`--gr-badge-*`, …) и ни одной из 94 ролей темы, кроме двух своих. Без компонентов —
предупреждение есть. Обещание доки зависит от селекции.

**Воспроизведение.** `repro/define-all.mjs` — пример портала байт в байт:
`components: 'all'` — блок `ocean` в 65 объявлений, из ролей темы только `--gr-bg` и
`--gr-primary`, `warnings: []`; `components: []` — 2 объявления и
`theme-extends-unresolved (opaque)`.

**Подтверждено на `main`:** `packages/granum/src/__tests__/tzPortal.test.ts` › «пункт ТЗ-2» › 2.1 —
предупреждение пропадает с компонентом, давшим базе структурный блок.

**Вопрос к пакету.** `theme-extends-unresolved` (или новый код) — когда у базы есть
тема-файл, даже если компоненты добавили к ней структурные блоки: наследуется не тема, а её
покомпонентный хвост. Подготовка приложения на `main` читает файлы тем провайдеров (селектор
первого блока и имена токенов) — наследовать и значения файла стало возможно.

**Критерий готовности.** Фикстура с темой-файлом и компонентом, у которого есть
`tokenDefinitions` той же темы: `extends` от неё даёт предупреждение либо наследует
значения файла.

### ТЗ-3. `@feugene/granum/contract` в рантайме провайдера: где granum жить у приложения

**Класс:** C. **Касается:** §4.2 (`./contract` — browser + node), C-5 / INV-CON-9 (peer),
N-1, `docs/*/getting-started.md`, `docs/*/ssr.md`, `docs/*/authoring-providers.md`. **Roadmap:** «Долги вне очереди» —
ломает SSR-деплой; если ответ окажется только
документацией, пункт уходит в 3.3.

**Что ожидает потребитель.**

- Портал: `installation.md:23` — «`@feugene/granum` | `^1.0` | конвейер CSS; на сборке, в
  бандл не попадает», `:66-67` — «`@feugene/granum` и движок — в `devDependencies`»;
  `getting-started.md:28-32`; `introduction.md:40`; `performance.md:78-80`.
- `docs/ru/getting-started.md:13-18` — «`yarn add -D @feugene/granum
  @feugene/granum-engine-wind vite` … `vite` — единственный peer, и нужен он только точкам
  входа `./build` и `./vite`»; `docs/ru/authoring-providers.md:5-7` — «JS провайдера ради
  резолюции не исполняется».
- `docs/spec.md:125` — `./contract`: «browser + node», то есть рантайм-импорт задуман.

**Что делает код и как устроены провайдеры.**

- Эталонная фикстура `fixtures/heavy-package` отдаёт дескриптор из entry компонента (`src/components/XhButton/index.ts`:
  `export { xhButtonConfig } from './config'`), и
  собранный чанк импортирует контракт:
  `dist/components/XhButton/chunks/XhButton-jv3UR9rr.js:2` — `import {
  defineGranumComponent } from "@feugene/granum/contract"`. В `package.json` фикстуры
  granum нет ни в `peerDependencies`, ни в `dependencies`.
- Ядро 1.0.21 сделано так же: 82 чанка `config-*.js` импортируют контракт
  (`dist/components/GrButton/chunks/config-C-jAgYtU.js:3`), granum объявлен обязательным peer.
- В клиентском бандле при `import { GrButton }` конфиг вытряхивается (`sideEffects`
  провайдера), granum — 0 байт. При `export *` из подпути контракт остаётся: +857 B gzip у
  `GrButton`.
- В Node без granum компонент не грузится:
  `import('@feugene/granularity/components/GrButton')` → `ERR_MODULE_NOT_FOUND Cannot find
  package '@feugene/granum' imported from …/GrButton/chunks/config-C-jAgYtU.js`. Vite SSR по
  умолчанию выносит пакеты из `node_modules` во внешние, значит серверный бандл грузит
  провайдер в рантайме, и при деплое с `--omit=dev` (granum в `devDependencies`, как велит
  быстрый старт) SSR падает. То же в тестах без бандлера.
- Стенд `apps/app-ssr` этого не ловит: фикстуры — симлинки воркспейса, Vite встраивает их в
  серверный бандл (`dist/server/entry-server.js` содержит `defineGranumComponent`,
  импортирует только `vue`).
- C-5 / `peer-missing` проверяет только доноров-провайдеров; что чанки провайдера
  импортируют `@feugene/granum/*`, а `package.json` granum не объявляет, не видит никто.

**Подтверждено на `main`:** `packages/granum/src/__tests__/tzPortal.test.ts` › «пункт ТЗ-3» — чанк компонента провайдера,
реэкспортирующего дескриптор, импортирует `@feugene/granum/contract`, `package.json` пакета
granum не объявляет, манифест без предупреждений. Быстрый старт (`getting-started.md`) ставит
granum с `-D`.

**Вопрос к пакету — какой путь правильный:**

1. Дескриптор — часть рантайм-API провайдера. Тогда провайдер MUST объявлять
   `@feugene/granum` peer-зависимостью, приложение держит его в `dependencies`, если код
   провайдера исполняется в Node (SSR с внешними пакетами, тесты, скрипты), быстрый старт и
   `ssr.md` говорят об этом, `granumProvider` пишет `peer-missing` и для самого granum.
2. Дескриптор — только для сборки. Тогда провайдер не реэкспортирует его из entry
   компонента (дескрипторы живут в `granum-provider/index.ts`), фикстура меняется, а
   `granumProvider` предупреждает, если entry компонента тянет `./contract`.
3. `granumProvider` встраивает или вырезает вызов `defineGranumComponent` (хелпер чистый,
   C-20), и в `dist` провайдера рантайм-импорта granum нет.

**Критерий готовности.** Выбранный путь записан в `getting-started`,
`authoring-providers`, `ssr` (ru/en); проверка в `granumProvider` (предупреждение в
манифесте или `peer-missing`); вариант SSR-стенда с провайдером, вынесенным во внешние (`ssr.external` или установка из
упакованного tarball), проходит `verify-ssr` в той
конфигурации зависимостей, которую предписывает дока.

### ТЗ-4. Guard и `'imports'` не видят импорт компонента из корня пакета

**Класс:** C. **Касается:** A-6, INV-JS-2, A-3, INV-SEL-5, ADR-6, §4.3 п.3, AC-4. **Roadmap:** «Долги вне очереди».

**Что ожидает потребитель.**

- Портал, `troubleshooting.md:61-63`: «По умолчанию это не молчит: `js.guard` роняет сборку
  на импорте компонента вне выборки».
- `docs/ru/usage-in-apps.md:62-63` — «Guard в `resolveId` ловит импорт компонента, которого
  нет в селекции, и называет импортёра»; `docs/spec.md:436` (A-6) — «распознавать импорты,
  попадающие в `components/<Name>/` любого провайдера графа»; `docs/invariants.md:118`
  (INV-JS-2) — «ни один модуль приложения не импортирует директорию компонента вне
  селекции». Про корневой импорт (барель, его генерирует `codegen` — B-14) дока молчит.

**Что делает код.** `vite/plugin.ts:186-195` — guard узнаёт только спецификатор
`<pkg>/components/<Name>`; `:255` — импортёры из `/node_modules/` пропускаются, так что
внутренние импорты бареля не проверяются тоже. Скан `'imports'` — тот же регэксп (`node/appSources.ts:26,67-68`);
выручает его только скан тегов (A-8), когда тег совпадает с
именем экспорта.

**Воспроизведение** (`repro/app-barrel`, Vite 8.2.2): селекция
`[{ provider: '@feugene/granularity', names: ['GrButton'] }]`, `App.vue` — `import { GrButton,
GrChip } from '@feugene/granularity'` и `<GrChip>draft</GrChip>`. `vite build` зелёный:
`[granum] 1 components, 198 classes matched, 0 without a rule`; код `GrChip` в бандле, 34 из
35 собственных классов `GrChip` в CSS нет. С импортом из подпути — `ComponentOutsideSelectionError`.

**Подтверждено на `main`:** `packages/granum/src/__tests__/tzPortal.test.ts` › «пункт ТЗ-4» — корневой импорт компонента вне
селекции собирается молча (тот же импорт подпутём — `ComponentOutsideSelectionError`);
`'imports'` не считает корневой импорт, когда тег не совпал с именем. В доках про корневой
импорт ни слова.

**Вопрос к пакету.** Починить: guard узнаёт именованный импорт из корня провайдера (`import { X } from '<providerId>'`,
где `X` — имя компонента этого провайдера) и выдаёт тот
же `component-outside-selection`; `'imports'` считает такие импорты. Или объяснить: строка в
`usage-in-apps.md` и `troubleshooting.md` (ru/en) — «корневой импорт guard не видит; при
явном списке импортируйте подпути», и уточнение A-6 / INV-JS-2.

**Критерий готовности.** Интеграционный тест рядом с AC-4: корневой импорт компонента вне
селекции при `guard: 'error'` валит сборку; при `'imports'` компонент входит в селекцию без
тега. Либо описанное ограничение в доке и в формулировке INV-JS-2.

### ТЗ-6. Опечатки и неизвестные ключи конфига проходят и типы, и рантайм-проверку

**Класс:** B. **Касается:** A-1, §4.3 п.3, INV-DIAG-3, §18.1 (форма `GranumConfig`). **Roadmap:** «Долги вне очереди».

**Что ожидает потребитель.** `docs/spec.md:425` (A-1) — «Конфиг MUST … валидироваться
типами и рантайм-проверкой формы; ошибки формы — `InvalidConfigError` с путём до поля»;
`docs/ru/usage-in-apps.md:45-47` — «Форма конфига проверяется при загрузке».

**Что делает код.**

- `config.ts:101-103` — `defineGranumConfig<T extends GranumConfig>(config: T): T`: обобщённый
  параметр отключает проверку лишних свойств у литерала. Конфиг с `appSource` (опечатка) и
  `themes.themeFiles` компилируется под `tsc --strict` без ошибок.
- `vite/validateConfig.ts:51-93` проверяет только известные поля; неизвестные проходят.
- Итог: опечатка `appSource` — классы разметки молча не генерируются (`appScan.classes: 0`),
  `themes.themeFiles` из v1 молча игнорируется, `pruneTokens: { appSources }` (место v1, см.
  `docs/ru/migration.md:90-91`) — тоже.

**Воспроизведение.** `repro/app-src/cfg-check.ts` + `tsconfig.json` → `tsc` exit 0;
`repro/unknown-keys.mjs` → `granum()` принимает конфиг, `warnings: []`,
`appScan.classes: 0`, файла из `themeFiles` в CSS нет.

**Подтверждено на `main`:** `packages/granum/src/__tests__/tzPortal.test.ts` › «пункт ТЗ-6» — `appSource`, `themes.themeFiles`,
`pruneTokens.appSources` проходят `validateGranumConfig`; `appSource` компилируется в
`defineGranumConfig` (`yarn typecheck`).

**Вопрос к пакету.** Сигнатура без обобщённого параметра (или с точным типом), неизвестные
ключи на любом уровне — `InvalidConfigError` с путём; для ключей v1 (`themes.themeFiles`,
`themes.baseFile`, `themes.tokensFile`, `pruneTokens.appSources`, `scan`) — подсказка, куда
они делись. Решить, ошибка это в 1.x или предупреждение: приложение с лишним ключом сейчас
собирается.

**Критерий готовности.** `validateConfig.test.ts`: неизвестный ключ верхнего и вложенного
уровня → `InvalidConfigError` с путём; тест типов (по образцу `tsconfig.client.json`): `appSource`
в `defineGranumConfig` — ошибка компиляции.

### ТЗ-7. Пакет-провайдер только с правилами: путь назван, но не описан

**Класс:** C. **Касается:** ADR-9 (последствия), E-10, E-18, M-7, C-21, C-23. **Roadmap:** «Горизонт 3 → 3.3 Второй
потребитель».

**Что ожидает потребитель.** `docs/ru/usage-in-apps.md:279-281` — «если цена важна, правила
приложения лучше вынести в отдельный пакет-провайдер»; `docs/roadmap.md:307-310` — витрина
так и сделала, «правила иконок уехали в провайдера без компонентов».

**Что есть.** В `docs/*/authoring-providers.md` нет ни слова о провайдере без компонентов:
`components: []`, `granumProvider({ indexEntry: false, engineModule })`, диалект, равный
диалекту приложения (иначе `engine-rules-skipped`), ограничения модуля правил (без FS, без
JSON-импорта с атрибутом — бандлер срезает `with { type: 'json' }`). Рабочий пример есть
только снаружи: портал, `packages/site-icons/{granum.provider.ts,vite.config.ts,src/engine.ts}`
(манифест: `components: {}`, `engine.module: "engine.js"`, отпечаток ванильный); приложение с
ванильным движком идёт быстрым путём.

**Подтверждено на `main`:** `packages/granum/src/__tests__/tzPortal.test.ts` › «пункт ТЗ-7» — сценарий работает: пакет без
компонентов с модулем правил того же диалекта даёт приложению класс правила,
`rulesLoaded: true`, пересчёта нет. В `authoring-providers.md` (ru/en) о таком пакете ни слова.

**Вопрос к пакету.** Это поддержанный сценарий или случайно работающий? Если поддержанный —
раздел «Провайдер только с правилами» в `authoring-providers.md` (ru/en) и фикстура.

**Критерий готовности.** Раздел в доке; фикстура `rules-only` и приложение-стенд с ванильным
движком: `reextract: ['none']`, класс правила генерируется (по образцу гейта 2.3).

### ТЗ-8. Классы приложения без правила не попадают в `unmatched`

**Класс:** B. **Касается:** INV-DIAG-2, A-19, §14 (последний абзац), E-9. **Roadmap:** «Долги вне очереди», низкий
приоритет.

**Что ожидает потребитель.** `docs/invariants.md:135` (INV-DIAG-2) — «Класс без правила никогда
не отбрасывается молча: он в `unmatched` отчёта и в `doctor`»; `docs/ru/architecture.md:85-87`;
`docs/ru/migration.md:74-75` и `MIGRATION.md:41-43` — «`classes.unmatched` должен быть пуст или
объяснён». Портал (`installation.md:147-151`) честно пишет, что класс иконки без правила
«пройдёт молча».

**Что делает код.** `node/report.ts:247-251` выбрасывает из `unmatched` всё, что пришло только из
`app` («Токены из исходников приложения без правила — норма (экстрактор берёт всё подряд)»).
Строка сборки — `0 without a rule`. Узнать можно только `granum why-css <class>`.

**Воспроизведение.** `repro/engine.mjs`: `App.vue` с `i-lucide-user` и
`not-a-rule-xyz`, ванильный движок → `unmatched: []`, `doctor: []`; `why-css i-lucide-user` →
«Rule: none … application source: src/App.vue».
