## Пункты

### ТЗ-2. Тема приложения поверх темы-файла: `extends` молчит

**Класс:** B (предупреждение). **Касается:** INV-THM-2, INV-THM-4, §14
(`theme-extends-unresolved`), §4.3 п.3. **Roadmap:** «Долги вне очереди».

**Решено на `main`, не выпущено:** блок темы приложения встаёт в слое `themes` после
файлов тем, раньше идущих в `names`, и на `<html data-theme="ocean">` больше не
проигрывает `:root` светлой; путь «своя тема поверх темы-файла» — `define` с `tokensRef` —
описан в `docs/{ru,en}/themes-and-tokens.md` («Перекрасить тему провайдера»).

**Что ожидает потребитель.**

- Портал, `src/content/ru/docs/theming.md:150-176`: «Своя тема может быть частью конфига, и
  тогда её значения проходят ту же резолюцию, что и встроенные» — `define: { ocean: {
  extends: 'dark', selector: '[data-theme="ocean"]', tokens: { 'gr-primary': '#4fd1e0',
  'gr-bg': '#062b32' } } }`.
- `docs/ru/themes-and-tokens.md` — «`extends` наследует значения провайдерской темы (только
  структурные: тема из файла непрозрачна, и отчёт скажет `theme-extends-unresolved`)»;
  `docs/ru/troubleshooting.md`.

**Что делает код.** Предупреждение выдаётся, только если у базы нет ни одного структурного
токена: `core/resolveThemes.ts` (`Object.keys(baseTokens).length === 0`). У темы-файла ядра
структурные токены есть от компонентов селекции, поэтому при `components: 'all'`
предупреждения нет, а `ocean` наследует 63 покомпонентных токена (`--gr-button-*`,
`--gr-badge-*`, …) и ни одной из 94 ролей темы, кроме двух своих. Без компонентов —
предупреждение есть. Обещание доки зависит от селекции.

**Воспроизведение.** `repro/define-all.mjs` — пример портала байт в байт:
`components: 'all'` — блок `ocean` в 65 объявлений, из ролей темы только `--gr-bg` и
`--gr-primary`, `warnings: []`; `components: []` — 2 объявления и
`theme-extends-unresolved (opaque)`.

**Подтверждено на `main`:** `packages/granum/src/__tests__/tzPortal.test.ts` › «пункт ТЗ-2» › 2.1 —
предупреждение пропадает с компонентом, давшим базе структурный блок.

**Вопрос к пакету.** `theme-extends-unresolved` (или новый код) — когда у базы есть
тема-файл, даже если компоненты добавили к ней структурные блоки: наследуется не тема, а её
покомпонентный хвост. Подготовка приложения на `main` читает файлы тем провайдеров (селектор
первого блока и имена токенов) — наследовать и значения файла стало возможно.

**Критерий готовности.** Фикстура с темой-файлом и компонентом, у которого есть
`tokenDefinitions` той же темы: `extends` от неё даёт предупреждение либо наследует
значения файла.

### ТЗ-7. Пакет-провайдер только с правилами: путь назван, но не описан

**Класс:** C. **Касается:** ADR-9 (последствия), E-10, E-18, M-7, C-21, C-23. **Roadmap:** «Горизонт 3 → 3.3 Второй
потребитель».

**Что ожидает потребитель.** `docs/ru/usage-in-apps.md:279-281` — «если цена важна, правила
приложения лучше вынести в отдельный пакет-провайдер»; `docs/roadmap.md:307-310` — витрина
так и сделала, «правила иконок уехали в провайдера без компонентов».

**Что есть.** В `docs/*/authoring-providers.md` нет ни слова о провайдере без компонентов:
`components: []`, `granumProvider({ indexEntry: false, engineModule })`, диалект, равный
диалекту приложения (иначе `engine-rules-skipped`), ограничения модуля правил (без FS, без
JSON-импорта с атрибутом — бандлер срезает `with { type: 'json' }`). Рабочий пример есть
только снаружи: портал, `packages/site-icons/{granum.provider.ts,vite.config.ts,src/engine.ts}`
(манифест: `components: {}`, `engine.module: "engine.js"`, отпечаток ванильный); приложение с
ванильным движком идёт быстрым путём.

**Подтверждено на `main`:** `packages/granum/src/__tests__/tzPortal.test.ts` › «пункт ТЗ-7» — сценарий работает: пакет без
компонентов с модулем правил того же диалекта даёт приложению класс правила,
`rulesLoaded: true`, пересчёта нет. В `authoring-providers.md` (ru/en) о таком пакете ни слова.

**Вопрос к пакету.** Это поддержанный сценарий или случайно работающий? Если поддержанный —
раздел «Провайдер только с правилами» в `authoring-providers.md` (ru/en) и фикстура.

**Критерий готовности.** Раздел в доке; фикстура `rules-only` и приложение-стенд с ванильным
движком: `reextract: ['none']`, класс правила генерируется (по образцу гейта 2.3).

### ТЗ-8. Классы приложения без правила не попадают в `unmatched`

**Класс:** B. **Касается:** INV-DIAG-2, A-19, §14 (последний абзац), E-9. **Roadmap:** «Долги вне очереди», низкий
приоритет.

**Что ожидает потребитель.** `docs/invariants.md:135` (INV-DIAG-2) — «Класс без правила никогда
не отбрасывается молча: он в `unmatched` отчёта и в `doctor`»; `docs/ru/architecture.md:85-87`;
`docs/ru/migration.md:74-75` и `MIGRATION.md:41-43` — «`classes.unmatched` должен быть пуст или
объяснён». Портал (`installation.md:147-151`) честно пишет, что класс иконки без правила
«пройдёт молча».

**Что делает код.** `node/report.ts:247-251` выбрасывает из `unmatched` всё, что пришло только из
`app` («Токены из исходников приложения без правила — норма (экстрактор берёт всё подряд)»).
Строка сборки — `0 without a rule`. Узнать можно только `granum why-css <class>`.

**Воспроизведение.** `repro/engine.mjs`: `App.vue` с `i-lucide-user` и
`not-a-rule-xyz`, ванильный движок → `unmatched: []`, `doctor: []`; `why-css i-lucide-user` →
«Rule: none … application source: src/App.vue».

**Подтверждено на `main`:** `packages/granum/src/__tests__/tzPortal.test.ts` › «пункты ТЗ-8 и ТЗ-9» › 8 — класс разметки без
правила подан движку, но в `unmatched` отчёта его нет. INV-DIAG-2 говорит обратное.

**Вопрос к пакету.** Фильтр обоснован — тогда INV-DIAG-2, `architecture.md`, `migration.md` и
`MIGRATION.md` говорят, что классы разметки приложения в `unmatched` не входят и проверяются
`why-css`. Или опция (поле отчёта, флаг `doctor`) для классов приложения, похожих на утилиты
словаря.

**Критерий готовности.** Формулировка INV-DIAG-2 совпадает с кодом, доки ru/en поправлены;
либо опция с тестом.

### ТЗ-9. Конфиг без `appSources` молча не генерирует классы разметки

**Класс:** C. **Касается:** A-11, INV-CSS-3, §4.3 п.3. **Roadmap:** «3.3 Второй потребитель»,
низкий приоритет.

**Что ожидает потребитель.** Портал, `installation.md:84` — «Минимальный рабочий конфиг —
движок, провайдер и больше ничего»; `packages/granum-engine-wind/README.md:12-15` — пример
конфига без `appSources`.

**Что делает код.** `node/appSources.ts:45-46` — без конфига скан пуст; `vite/plugin.ts:233-240`
предупреждает только при `components: 'imports'`; строка сборки о скане молчит.

**Подтверждено на `main`:** `packages/granum/src/__tests__/tzPortal.test.ts` › «пункты ТЗ-8 и ТЗ-9» › 9 — без `appSources`
разметка не сканируется, предупреждений нет, утилиты разметки в CSS не попадают. Пример в
README движка без `appSources`.

**Вопрос к пакету.** Строка лога или предупреждение, когда `appSources` не задан («classes of the
application markup are not scanned»), либо явная фраза в таблице `usage-in-apps.md` («без него
классы разметки не генерируются») и `appSources` в примере README движка.

**Критерий готовности.** Строка лога с тестом в `vitePlugin.test.ts` или правка доки ru/en и
README.
