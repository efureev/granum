# ТЗ: движок — выбор приложения, диалект — контракт словаря

> Статус: **ТЗ изменения, не реализовано**. Дата: 2026-09-26. Ломает контракт
> без обратной совместимости: `@feugene/granum@0.1.0` опубликован как проверка
> и потребителей не имеет. Реализация — [«Этап 8»](./plan.md).
>
> Нормативные разделы ТЗ ([`spec.md`](./spec.md) §5–§8, §14) правятся **в конце**
> этапа, когда поведение уже существует: пакетный `SPEC.md` порождается из них и
> уезжает в опубликованный пакет, а документ, описывающий не сделанное, — тот
> самый тихий обман, от которого пакет и защищается.

## 1. Зачем

Сегодня granum вендорит ядро UnoCSS внутрь пакета и зовёт его `'builtin'`.
Интерфейс движка сменный, но две вещи сделаны неправильно.

**Первая: диалект запекается в артефакт и нигде не записан.** Сборка провайдера
прогоняет свой движок дважды: экстрактором добывает кандидатов из чанков,
генератором отбрасывает те, для которых правила нет (B-6). В манифест уезжает
уже отфильтрованный список классов, и в нём не сказано, чей движок фильтровал.
Отсюда два исхода при несовпадении движков у пакета и приложения, и второй
опасен:

- класс, который знал движок пакета и не знает движок приложения, попадает в
  `classes.unmatched` — это громко и уже работает;
- класс, который движок приложения сгенерировал бы, а движок пакета не знал, в
  манифест не попал вовсе — приложение о нём не узнает никогда. Тихая потеря,
  запрещённая INV-DIAG-3.

**Вторая: правила непортируемы, а контракт делает вид, что их можно смешивать.**
Правило — функция против контракта конкретного генератора: своя семантика
вариантов, своё чтение темы, свой разбор произвольных значений. Пакет A с
правилами одного движка, пакет B с правилами другого и приложение с третьим — не
задача слияния. Сегодня все правила без разбора складываются в один генератор.

## 2. Решение в одном абзаце

Движок утилит уезжает из ядра в отдельный пакет; приложение выбирает его само и
передаёт инстансом. Каждый движок объявляет **диалект** — идентичность словаря
классов. Сборка провайдера записывает диалект в манифест как факт о
происхождении данных. Приложение сверяет диалекты и при несовпадении не
угадывает, а пересчитывает классы пакета своим движком и называет разницу.
Пакет, который не пользуется утилитами вовсе, объявляет диалект `null` и
работает с любым движком.

## 3. Модель диалекта

**Диалект — это словарь, а не реализация.** Вендоренный форк preset-mini и
адаптер над настоящим `unocss` с тем же пресетом дают одинаковые имена классов,
значит объявляют один диалект. Реализацию различает `name`.

Формат: `<vendor>/<vocabulary>@<major>`, сравнение — строгим равенством строк.
Ни диапазонов, ни вычисления подмножеств: «похожие» словари — источник тихих
расхождений, а точный ответ по каждому классу всё равно даёт `unmatched`.

| ID | Требование |
|---|---|
| E-1 | `dialect` MUST соответствовать `/^[a-z0-9][\w.-]*\/[\w.+-]+@\d+$/`; сравнение — равенством. Примеры: `unocss/preset-mini@66`, `unocss/preset-mini+granum@66`, `granum-fixtures/atoms@1`. |
| E-2 | **Любая опция движка, меняющая набор генерируемых имён, MUST менять диалект.** Встроенные доп-правила выключены — это другой диалект (`unocss/preset-mini@66` против `unocss/preset-mini+granum@66`), потому что `divide-y`, `space-x-4` и `tabular-nums` есть только во втором. Опция, меняющая только вывод (префикс кастомных свойств), диалект MUST NOT менять. |
| E-3 | Диалект `null` означает, что артефакт не зависит ни от одного словаря утилит. В манифесте он допустим тогда и только тогда, когда у всех компонентов пусты и `classes`, и `safelist`; читатель это проверяет. |

## 4. Интерфейс движка (`./engine`)

```ts
interface GranumEngine {
  /** Реализация: для диагностики. */
  readonly name: string
  /** Словарь: по нему принимаются решения (E-1, E-2). */
  readonly dialect: string
  extract: (code: string, id: string) => ReadonlySet<string>
  generate: (input: EngineInput) => Promise<EngineOutput>
}
```

| ID | Требование |
|---|---|
| E-4 | Ядро `@feugene/granum` MUST NOT содержать реализации движка: ни вендоренного кода, ни правил, ни пресетов. `./engine` отдаёт типы, `extractClasses` (экстрактор классоподобных токенов, пригодный авторам движков) и `parseDialect`. |
| E-5 | Встроенный движок переезжает в `@feugene/granum-engine-mini`: тот же вендоренный форк UnoCSS 66.7.5 с доп-правилами, ноль зависимостей, `THIRD_PARTY_NOTICES.md`, скрипт вендоринга и golden-тест — там же. Фабрика `miniEngine(options)`; `options.extraRules: false` даёт другой диалект (E-2). |
| E-6 | Движок MUST быть чист и детерминирован, без глобального состояния между вызовами (INV-ENG-1); каждый класс входа MUST попасть либо в `matched`, либо в `unmatched` (INV-ENG-2); порядок правил — встроенные < провайдеров в порядке графа < приложения, последнее совпавшее побеждает (INV-ENG-3). |
| E-7 | Правила приложения передаются фабрике его движка, а не конфигу granum: у конфига нет и не появляется поля для правил. Так решается случай «приложению нужен свой класс», который сегодня требует заменить движок целиком. |

## 5. Конфиг приложения

| ID | Требование |
|---|---|
| A-E1 | `engine` в `granum.config.*` MUST быть обязательным и принимать **инстанс** `GranumEngine`. Строка `'builtin'` и объект опций из конфига убираются: выбор реализации и её настройка — дело приложения, а не granum. |
| A-E2 | Отсутствие `engine`, объект без `dialect` или диалект, не проходящий E-1, — `InvalidConfigError` с путём до поля. |

```ts
// granum.config.ts
import { defineGranumConfig } from '@feugene/granum/vite'
import { miniEngine } from '@feugene/granum-engine-mini'

export default defineGranumConfig({
  providers: ['@acme/ui'],
  engine: miniEngine({ rules: [['icon-user', { background: 'url(...)' }]] }),
  appSources: { dirs: ['src'] },
})
```

## 6. Контракт провайдера

| ID | Требование |
|---|---|
| C-E1 | `provider.engine` принимает форму `{ dialect, rules?, variants?, preflights? }`. Если задано хоть одно из `rules`/`variants`/`preflights`, `dialect` MUST быть задан: правило без объявленного словаря непригодно к проверке. |
| C-E2 | Провайдер MAY объявить `engine: { dialect }` без правил — как утверждение о словаре своих классов. Сборка сверяет утверждение с диалектом движка, которым её запустили; расхождение — `EngineDialectMismatchError`, а не молчаливая запись чужого диалекта в манифест. |
| C-E3 | Пакет, не пользующийся утилитами (вся отделка — свой CSS и токены), MUST иметь право не объявлять ничего. Диалект его манифеста — `null` (E-3). |
| C-E4 | `granumProvider({ engine })` MUST требовать инстанс движка: диалект артефакта берётся из него, и «движок по умолчанию» у сборки провайдера исчезает. |

## 7. Манифест: версия формата 2

Корневое поле `engineModule` убирается, вместо него блок `engine`:

```json
{
  "granum": 2,
  "engine": {
    "dialect": "unocss/preset-mini+granum@66",
    "name": "granum-engine-mini",
    "version": "66.7.5",
    "module": "granum-provider/engine.js"
  }
}
```

| ID | Требование |
|---|---|
| M-E1 | Версия формата MUST стать `2`. Читатель отклоняет любую другую, включая `1`, ошибкой `UnsupportedManifestVersionError` — громко и без попытки прочитать (M-4). |
| M-E2 | Блок `engine` MUST присутствовать всегда. `dialect` — строка по E-1 либо `null`; `name` — непустая строка; `version` — необязательная строка; `module` — путь относительно манифеста либо `null`. |
| M-E3 | Читатель MUST отклонять манифест, где `dialect: null`, а у какого-нибудь компонента непусты `classes` или `safelist` (E-3), — `InvalidManifestError('dialect-without-classes')`. |
| M-E4 | Правила движка в JSON не встраиваются: `module` ссылается на ESM-модуль с `export default { rules, variants, preflights }` в типах granum. Путь задаёт автор опцией плагина; провайдер, объявивший правила без пути, получает предупреждение `engine-module-missing` (уже реализовано). |

## 8. Сверка на стороне приложения

| ID | Требование |
|---|---|
| A-E3 | Для каждого провайдера приложение MUST сравнить `manifest.engine.dialect` с диалектом своего движка и действовать по таблице ниже. Решение MUST приниматься до генерации CSS. |
| A-E4 | При несовпадении диалектов классы каждого компонента MUST быть извлечены заново из его `files` движком приложения тем же обходом, что у медленного пути объектной формы (R-6), и сравнены со списком манифеста. |
| A-E5 | `safelist` пересчёту MUST NOT подлежать: это авторское объявление, а не производная. Запись без правила у движка приложения попадает в `unmatched` отчёта и `safelist-dead` доктора — как сейчас. |
| A-E6 | Модуль правил провайдера MUST загружаться только при равенстве диалектов. Иначе — предупреждение `engine-rules-skipped`; классы, опиравшиеся на эти правила, окажутся в `unmatched`, и это честный исход. |

| Диалект манифеста | Что делает granum | Что видит разработчик |
|---|---|---|
| `null` | быстрый путь, пересчёта нет | ничего: пакет ни от какого словаря не зависит |
| равен диалекту движка | быстрый путь, классы из манифеста | ничего, это норма |
| другой, пересчёт дал тот же набор | классы из пересчёта | `provider-dialect-checked` в отчёте: совместимость измерена, а не обещана |
| другой, наборы разошлись | классы из пересчёта | `provider-dialect-mismatch` с числами и списками `lost` / `gained` |
| другой, а пакет привёз `module` | правила не грузятся | `engine-rules-skipped` |

Пересчёт при несовпадении вытаскивает ровно те классы, которые пакет потерял на
своей сборке, потому что его движок их не знал. Сегодня такая потеря молчит.

| D-E2 | `doctor` MUST иметь коды `provider-dialect-mismatch` (warn, с числами), `engine-rules-skipped` (warn) и показывать диалект каждого провайдера рядом с его формой. |

## 10. Ошибки

| Условие | Ошибка | Когда |
|---|---|---|
| `dialect` не проходит E-1 | `InvalidProviderError('invalid-dialect')` | регистрация |
| правила есть, `dialect` нет | `InvalidProviderError('rules-without-dialect')` | регистрация |
| утверждённый диалект ≠ диалект движка сборки | `EngineDialectMismatchError` | сборка провайдера |
| `engine` в конфиге отсутствует или без диалекта | `InvalidConfigError` | загрузка конфига |
| `dialect: null` при непустых классах | `InvalidManifestError('dialect-without-classes')` | чтение манифеста |
| версия формата ≠ 2 | `UnsupportedManifestVersionError` | чтение манифеста |

## 15. Чего это ТЗ не делает

**Не вводит цепочку движков.** Два словаря в одном слое `utilities` ломают
INV-ENG-2 и INV-ENG-3: у класса становится два вердикта, а «последнее совпавшее
побеждает» теряет смысл. Если такая потребность появится, форма известна и
ограничения жёсткие: разные диалекты, разные префиксы переменных, все preflight
до всех утилит, класс достаётся первому совпавшему, и отчёт называет, чей движок
его взял. Это отдельное расширение, а не часть этапа.

**Не даёт вычислять совместимость словарей.** Ни подмножеств, ни диапазонов
версий: совместимость либо измерена пересчётом, либо не утверждается.

**Не спасает от провайдера, потерявшего классы на своей сборке.** Пакет,
использующий класс, которого не знает его собственный движок, теряет его молча —
это дефект на стороне пакета. Приложение с другим диалектом такой класс, наоборот,
вернёт: пересчёт найдёт его в `files`.
