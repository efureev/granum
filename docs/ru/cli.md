# CLI `granum`

> 🇬🇧 English version: [`../en/cli.md`](../en/cli.md).

Все команды работают **без сборки приложения** — по манифестам провайдеров и
`granum.config.*`; исключение — `report`, читающий `granum-report.json`
собранного приложения. Первый аргумент — путь к конфигу; корень приложения —
его директория.

```bash
granum doctor  granum.config.ts [--json] [--strict] [--allow=code,code]
               [--code=<code>] [--component=<providerId:Name>] [--components]
granum explain granum.config.ts <providerId:Component> [--json]
granum why-css granum.config.ts <class> [--json]
granum tokens  granum.config.ts <providerId:Component> [--deep] [--json]
granum themes  granum.config.ts [--json]
granum prune   granum.config.ts [--json] [--strict]
granum report  [dist/granum-report.json] [--json] [--strict]
granum audit   [<dist-dir>] [--json] [--strict] [--root=<dir>]
granum codegen [<package-dir>] [--check] [--json] [--targets=barrel,exports,manifest,registry]
```

Конфиг `.ts` загружается через `vite` приложения (`loadConfigFromFile`), а
если `vite` из корня не резолвится — нативным `import()`. Принимаются
экспорты `default`, `granum` и `config`.

## Коды выхода

| Код | Когда |
|---|---|
| `0` | чисто |
| `1` | найдены ошибки; с `--strict` — и предупреждения; ошибка выполнения |
| `2` | неверный вызов: нет команды, конфига или предмета; неизвестный флаг; значение у булева флага (`--strict=true`); флаг со значением без значения |

Флаги разбираются строго, потому что команда стоит гейтом в CI: опечатка или не
та форма флага — код `2`, а не тихо выключенная проверка. Флаг со значением
пишется и `--prefix=Gr`, и `--prefix Gr`.

`doctor` возвращает `1` при любом `error` независимо от `--strict`;
`explain`, `tokens` и `why-css` — `1`, если предмет не найден; `themes` — всегда `0`; `prune` — `1`
только с `--strict` и при наличии удаляемых токенов; `report` — `1` с
`--strict`, если есть классы без правила или токены без объявления; `codegen` —
`1` с `--check`, если реестры устарели, и при ошибке генерации.

## `doctor`

Полный отчёт о конфигурации: провайдеры и их форма, селекция в порядке
зависимостей, активная тема и её источник, режимы с парами, превью, проверенные
файлы и диагностика. Уровни: `error` — сборка обязана сломаться, `warn` — законно, но
подозрительно.

| Код | Уровень | Что значит |
|---|---|---|
| `missing-file` | error | файл манифеста отсутствует на диске |
| `apply-not-expanded` | error | в CSS провайдера остался `@apply` — пересоберите провайдер плагином |
| `boundary` | error | чанк провайдера импортирует `node:*` или node-entry granum |
| `important-in-provider-css` | warn | `!important` внутри слоя инвертирует порядок каскада |
| `safelist-redundant` | warn | safelist дублирует статически извлечённые классы |
| `css-double-delivery` | warn | CSS компонента и инлайнится, и импортируется его чанком |
| `safelist-dead` | warn | запись safelist без правила у движка |
| `token-undefined` | warn | токен нужен компоненту извне, но не объявлен ни одним слоем. Потребление с fallback, токен, который компонент присваивает сам (в том числе переменная `v-bind()` из `<style>`), и `dynamicTokens` находкой не считаются |
| `token-fallback-only` | warn | компонент читает токен только через `var(--x, запасное)`, и ни один слой его не объявляет: компонент всегда рисует запасное значение — например, токен переименовали. Намеренный хук объявите в `hookTokens` дескриптора; `dynamicTokens` находкой не считаются |
| `token-conflict` | warn | токен пишут два пакетных слоя — компонент поверх данных темы или два компонента; показана цепочка и итог. Значения приложения конфликтом не считаются |
| `component-theme-unknown` | warn | компонент кладёт токены для темы, которой нет ни в одном каталоге графа: они не применятся |
| `component-mode-missing` | warn | у компонента нет файла режима сборки ни для него, ни для его предков: литералы взяты из режима по умолчанию — например забытый `dark.json`; значение, одинаковое во всех режимах, место в `root.json` |
| `theme-mode-missing` | warn | то же для данных активной темы: у режима сборки и его предков по `extends` значения токена нет, и литерал взят из режима по умолчанию. Значение, одинаковое во всех режимах, место в `root` темы |
| `mode-extends-unresolved` | warn | база `modes.define` — ни режим темы, ни другой `define`; режим наследует режим по умолчанию |
| `mode-extends-cycle` | warn | `modes.define` наследуют друг друга по кругу; цепочка обрывается на режиме по умолчанию |
| `override-skipped` | warn | `strictTokens` отбросил override токена, которого нет ни в данных темы, ни в токенах компонентов |
| `provider-without-manifest` | warn | провайдер передан объектом, а `baseUrl` не каталог на диске: классы и потребление неизвестны |
| `provider-scanned` | warn | провайдер передан объектом: классы и токены просканированы по его `dist` приложением (медленный путь, без графа бандлера) |
| `provider-dialect-mismatch` | warn | пакет собран движком другого словаря: его классы пересчитаны движком приложения, а не взяты из манифеста |
| `engine-rules-skipped` | warn | пакет привёз правила чужого словаря — они не загружены, опиравшиеся на них классы уйдут в `unmatched` |
| `provider-classes-recovered` | warn | движок приложения знает классы, которых в манифесте нет: сборка пакета их потеряла |
| `provider-classes-dropped` | warn | у классов из манифеста нет правила у движка приложения; они остаются во входе движка и в `unmatched` |
| `unused-provider` | warn | провайдер ничего не приносит в сборку |
| `subcomponents-missing` | warn | в `exports` пакета есть подпути частей составных компонентов, а манифест их не записал: провайдер собран прежней версией granum, и guard с селекцией этих частей не видят — пересоберите его |

### Вывод, который не растёт вместе с находками

На дизайн-системе из восьми пакетов находок бывает несколько десятков, а
компонентов — больше сотни. Разворачивать всё подряд бессмысленно: важное
теряется. Поэтому по умолчанию:

- **ошибки печатаются целиком и первыми** — они ломают сборку, и прятать их за
  флагом нельзя ни при каком объёме;
- предупреждения, если их больше дюжины, сводятся в таблицу по кодам с числами,
  в порядке серьёзности, и каждая строка подсказывает свой флаг;
- перечисление внутри находки (классы safelist, потерянные имена) сворачивается
  до трёх элементов и счётчика;
- список компонентов сворачивается в одну строку с суммами.

```
Diagnostics (errors: 0, warnings: 74):
  ⚠ token-undefined               1   --code=token-undefined
  ⚠ important-in-provider-css     1   --code=important-in-provider-css
  ⚠ safelist-dead                 2   --code=safelist-dead
  ⚠ safelist-redundant           70   --code=safelist-redundant
```

Детали — по требованию: `--code=<code>` печатает все находки одного кода с
полными перечислениями, `--component=<providerId:Name>` сужает до одного
компонента и его находок, `--components` разворачивает список. `--json` не
сворачивает ничего и предназначен для скриптов.

### Записанный долг: `--allow`

`--strict` роняет гейт на любом предупреждении. Часть их бывает осознанным
долгом — например `safelist-redundant`, чистка которого идёт отдельной работой.
Перечислите такие коды в `--allow`, и гейт их стерпит, продолжая печатать и
считать:

```bash
granum doctor granum.config.ts --strict --allow=safelist-redundant,safelist-dead
```

Флаг существует, чтобы вокруг доктора не заводили скрипт-обёртку: она неизбежно
расходится с самим доктором. Неразрешённые предупреждения печатаются в stderr со
счётчиками по кодам, чтобы в логе CI была видна причина, а не только код выхода.

`--json` отдаёт рядом с каждым провайдером его диалект, отпечаток словаря,
источник классов (`manifest` или `re-extracted`) и факт загрузки правил, а в
корне — движок приложения с его диалектом и отпечатком. Почему решений два и
почему они разные — [движки и диалекты](./engines-and-dialects.md).

## `audit`

Проверка **собранного** дистрибутива: что из пакетов доехало, а что обязано было
исчезнуть. Единственная команда, которая смотрит не на резолюцию, а на результат.

```bash
granum audit dist
granum audit dist/client --root=.      # SSR: ассеты в подкаталоге
granum audit dist --strict             # плюс находки отчёта сборки
granum audit dist --json               # для скрипта в CI
```

Конфиг не нужен: селекция и список провайдеров берутся из
`dist/granum-report.json`, а состав компонентов и объявленные токены — из
манифестов провайдеров. Поэтому команду можно поставить в прогон **чужого**
репозитория: достаточно его `dist`. Пустая селекция — не ошибка: приложение может
брать у пакета только правила движка, и аудит тогда проверяет, что компоненты
пакетов в дистрибутив не доехали. Ошибка — только отчёт без селекции и без
списка провайдеров: судить не по чему.

Что называется находкой:

| Находка | Почему это дефект |
|---|---|
| уникальный класс невыбранного компонента в CSS | компонент не вырезан: селекция протекла |
| собственный CSS невыбранного компонента | его `styles.css` инлайнился, хотя компонент не выбран |
| класс выбранного компонента, которого нет в CSS | обратная ошибка: обещали и не доставили |
| токен, который план обрезки назвал удаляемым, в дистрибутиве и недостижим | мёртвый груз: обрезка (`pruneTokens.mode: 'on'`) обещала снять и не сняла |
| класс без правила движка, токен без объявления | только с `--strict`: этим занимается `doctor` |

Вердикт выносится по CSS, а не по JS. Раскладку чанков выбирает бандлер, и класс
невыбранного компонента лежит в общем чанке не потому, что tree-shaking не
сработал; granum на JS не влияет вовсе (A-7). Поэтому колонка `js` в выводе —
информация, а не обвинение.

Чего аудит не вменяет:

* **класс, общий с выбранным компонентом** (`flex` есть у обоих) — в CSS он
  приехал по праву; то же касается `safelist` выбранного компонента: тоновая
  утилита кнопки едет именно оттуда;
* **класс из разметки самого приложения** — он к компоненту отношения не имеет,
  отчёт сборки перечисляет такие классы отдельно;
* **класс, которому движок не нашёл правила**, — в CSS его и не могло быть, про
  него говорит `unmatched`;
* **недостижимый токен при обрезке `off` или `report`** — снимать его никто не
  обещал; при `on` — если его сохранил план обрезки (`keep`, `dynamicTokens`,
  override, структурный токен): эти корни аудиту не видны, он называет такие
  токены сведением;
* **объектный провайдер** — пакета с манифестом у него нет, судить о составе не
  по чему; аудит называет его сведением;
* **переменные preflight движка (`--un-*`)** — фиксированная цена движка, не
  токен пакета; аудит называет их отдельной строкой.

Если в отчёте сборки нет `classes.app` (приложение собрано granum старше
0.6.0), отличить `gap-3` из `App.vue` от протёкшего класса нечем. Аудит в этом
случае печатает такие строки отдельным списком «Not judged» и код возврата не
роняет: пересборка возвращает проверку в строй.

Код возврата `1` при любой находке — команду можно поставить гейтом в CI.

## `explain`

Почему компонент в сборке (`selected`, `dependency`, `not-selected`,
`unknown`), кратчайшая цепочка от корня селекции, кто его требует, и что он
приносит: классы, safelist, CSS, файлы, потребляемые и объявляемые токены.
Корни селекции — те же, что у сборки: список `components` или, при
`components: 'imports'`, импорты и PascalCase-теги разметки. Ключ или имя части
составного компонента (`@acme/ui:XhListItem`) `explain` и `tokens` сводят к
владельцу и называют часть в отчёте (`part` в `--json`).

## `why-css`

Каким каналом класс попал в CSS — статика манифеста, safelist, селектор в
CSS компонента, исходники приложения, а также `manifest-lost` (класс из
манифеста, который движок приложения не смог пересчитать) — и каким правилом
движка сгенерирован (источник, слой, селектор). `Rule: none` означает
класс-крючок, опечатку или чужой словарь.

Для непокрытого класса из пакета печатается раздел `Vocabularies`: чем и для
какого словаря собран пакет, какой движок и диалект у приложения, загружены ли
правила пакета — и два выхода из этого: движок того же диалекта либо своё
правило в фабрике своего движка.

## `tokens`

Что компонент объявляет и потребляет; для каждого токена — откуда значение
(`own`, `component`, `theme`, `provider`, `app`, `none`) и цепочка слоёв по каждому
режиму активной темы: тема и режим, из которых пришло значение (`component
@acme/ui:XhButton (paper/dark)` у режима `ink-dim`). `--deep` включает зависимости
компонента.

## `themes`

Каталог тем графа по индексу манифеста владельца, без чтения данных тем: id,
название, родитель, режимы с режимом по умолчанию, ссылка на дизайн-систему.
Активная тема и превью помечены.

```
granum themes
=============

Catalog: @acme/tokens (2 theme(s), default: slate)

  • clay — Глина (extends slate)
      modes: light, dark (default: light)
  • slate — Сланец [active]
      modes: light, dark (default: light)
      docs: https://example.com/themes/slate
```

## `prune`

Что удалит обрезка и что сохранит с причиной — по тому же плану, которым
пользуется сборка; эмиссию команда не меняет. Байты «до → после» по файлам.

## `report`

Читает `granum-report.json`: селекция, тема, режимы и превью, классы без правила с
источниками, safelist, покрытый статикой, план обрезки, размеры слоёв
raw/gzip/brotli, предупреждения.

## `codegen`

Запускается в пакете-провайдере (аргумент — его корень, по умолчанию текущий
каталог) и приводит реестры в соответствие с `src/components`: barrel
`src/index.ts`, subpath-экспорты компонентов и `./granum.manifest.json` в
`package.json`, импорты конфигов и записи в `src/granum-provider/index.ts`.
Генератор пишет только внутрь размеченных блоков `<granum:components>`,
`<granum:components:imports>`, `<granum:components:registry>`; всё вокруг
принадлежит пакету.

```bash
granum codegen                       # все четыре цели
granum codegen --check               # в CI: код 1, если реестры устарели
granum codegen --targets=barrel,exports --prefix=Xh
```

`--prefix` — префикс имён компонентов (по умолчанию `Gr`), от него строится
имя экспорта конфига (`grAlertConfig`). Если в директории есть каталоги
компонентов, но ни один не начинается с префикса, генератор падает с
`no-components-with-prefix` и ничего не пишет: опечатка в префиксе иначе
вычистила бы все реестры. `--components-dir`, `--barrel`,
`--registry` переопределяют пути; `--subcomponents` добавляет алиасы
`exports` на части составных компонентов — сборка провайдера записывает их в
манифест владельца, и приложение судит по части владельца; `--exports=import`
пишет строковые subpath без `types` (пакет без деклараций). Нестандартные цели
(`markedBlock`) — через программный API `@feugene/granum/codegen`.

## Программный доступ

Все функции и форматтеры экспортируются из `@feugene/granum/node`:

```ts
import { formatDoctorReport, granumDoctor, loadGranumConfigFile, prepareApp } from '@feugene/granum/node'

const { config, root } = await loadGranumConfigFile('granum.config.ts', process.cwd())
const app = await prepareApp(config, root)
const report = await granumDoctor(app)
console.log(formatDoctorReport(report))
```

В CI: `granum doctor granum.config.ts --strict` до сборки и
`granum report --strict` после.
