# Серверный рендер

> 🇬🇧 English version: [`../en/ssr.md`](../en/ssr.md).

granum не требует от SSR ничего особенного, но две вещи нужно решить осознанно:
откуда берётся CSS и кто выбирает тему. Обе решаются один раз и дальше не
мешают. Рабочий пример целиком — стенд [`apps/app-ssr`](../../apps/app-ssr).

## CSS: собирать по модулям не нужно

Весь CSS приложения — один ассет с пятью каскадными слоями, на который ссылается
шаблон. Поэтому обычная для SSR работа «собрать стили отрендеренных модулей и
вписать их в ответ» здесь не нужна: собирать нечего, ссылка уже в шаблоне.

Серверный вход `virtual:granum.css` не импортирует вовсе — это делает только
клиентский:

```ts
// src/entry-client.ts
import 'virtual:granum.css'
```

```ts
// src/entry-server.ts — стилей не импортирует
import { renderToString } from '@vue/server-renderer'
```

Так же решается вопрос о `--ssrManifest`: он нужен тогда, когда CSS разрезан по
маршрутам и каждому ответу требуется свой набор ссылок. У granum набор один на
всё приложение, поэтому и манифест ни к чему.

## Тему выбирает сервер

Токены всех тем уже лежат в CSS. Переключение темы — это приведение DOM в
состояние, при котором нужный блок начинает совпадать: атрибут, класс или ничего,
если тема эмитирована под `:root`. Знание о том, какой селектор у какой темы,
есть только у сборки, и в рантайм оно приезжает манифестом:

```ts
import manifest from 'virtual:granum/themes'

manifest.themes
// [{ name: 'light', activation: { type: 'root' } },
//  { name: 'dark',  activation: { type: 'attribute', name: 'data-theme', value: 'dark' } }]
```

Если тему выбирает браузер после гидрации, первый кадр всегда чужой: сервер отдал
одну тему, клиент немедленно переключил на другую. Поэтому решение принимается на
сервере и записывается в открывающий тег документа.

```ts
// src/entry-server.ts
function rootAttributes(manifest, name) {
  const { activation } = manifest.themes.find(theme => theme.name === name) ?? {}
  if (activation?.type === 'attribute')
    return ` ${activation.name}="${activation.value}"`
  if (activation?.type === 'class')
    return ` class="${activation.value}"`
  return ''
}
```

Пустая строка здесь — законный результат, а не ошибка: тема с активацией `root`
активна, пока не активирована другая, и писать на корень ей нечего.

Имя темы из запроса обязательно сверяется с манифестом. В CSS есть только те
темы, что перечислены в `themes.names` конфига; имя не из этого списка означает,
что блока токенов под него не эмитировано, и активировать попросту нечего.
Отдавайте тему по умолчанию, а не страницу без токенов: пустой экран без
объяснения хуже, чем не та тема.

## Клиент читает тему, а не выбирает заново

Контроллер поднимается поверх уже применённого состояния:

```ts
// src/entry-client.ts
const controller = createThemeController(manifest, {
  initial: readActiveTheme(manifest, document.documentElement),
})
```

`readActiveTheme` — обратная операция к `rootAttributes`: она сравнивает
активацию каждой темы с тем, что стоит на корне документа. Контроллер стартует с
найденной темой и корень не трогает, поэтому первый клиентский кадр совпадает с
серверным до атрибута.

Сохранённый выбор пользователя из `localStorage` на старте не читается намеренно.
Если его читать, сервер отдаст одну тему, а клиент переключит на сохранённую —
ровно та вспышка, от которой SSR и уходят. Выбор должен доехать до сервера сам:
куки, заголовок, часть адреса.

## Разметка не зависит от источника темы

Контроллер — вещь браузерная. Чтобы разметка получилась одинаковой на обеих
сторонах, компоненты не должны его знать: им нужно имя активной темы и способ её
сменить.

```ts
export interface ActiveTheme {
  readonly name: string
  readonly list: readonly string[]
  readonly set: (name: string) => void
}
```

На сервере `set` — пустая операция, в браузере он зовёт контроллер. Приложение
прокидывает эту пару через свой механизм внедрения зависимостей, и разметка
получается одинаковой с обеих сторон.

## Рантайм в Node

Точка входа `@feugene/granum/runtime` объявлена браузерной: без `node:`-импортов
и без внешних зависимостей. «Браузерная» не значит «падает на сервере»: без DOM
контроллер конструируется, отвечает на вопросы о списке и текущей теме и просто
не применяет её. Это позволяет пользоваться им на сервере для проверки имени темы.

## Что проверять у себя

Стенд `apps/app-ssr` проверяет это скриптом, который импортирует собранный
серверный бандл и рендерит им. Минимальный набор для своего приложения:

1. один и тот же запрос даёт ту же разметку;
2. активная тема видна в разметке, и чтение с корня возвращает ту же тему;
3. старт контроллера не меняет корень, а переключение меняет;
4. неизвестное имя темы откатывается к теме по умолчанию;
5. ассет CSS один, и шаблон на него ссылается.
