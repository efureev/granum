# Темы и токены

> 🇬🇧 English version: [`../en/themes-and-tokens.md`](../en/themes-and-tokens.md).

Токен — CSS custom property (`--th-accent`). **Тема** — дизайн-язык: полный набор
значений токенов без селекторов, режимонезависимые (`root`) и по **режимам**
(`light`, `dark`, дальше любые). В сборке приложения ровно одна активная тема;
её режимы уезжают в CSS все сразу и переключаются в рантайме атрибутом на корне.
Все имена в данных, конфигах и файлах токенов пишутся **без** `--`: префикс
добавляет генератор, а ключ с `--` — ошибка (`InvalidTokenKeyError` у провайдера,
`InvalidConfigError` с путём до поля у приложения).

## Тема, режим, пара

| Понятие | Что это |
|---|---|
| тема | `GranumThemeData`: `id` (slug `^[a-z][a-z0-9-]*$`), `title`, `root`, `modes`, `defaultMode` (по умолчанию `light`), `baseCss`, `extensions` |
| режим | значения режимозависимых токенов: `{ colorScheme, tokens, extends?, title?, fallbacks? }`; имя — slug без дефиса, `root` запрещено |
| пара | значение атрибута активации: `<тема>-<режим>` (`slate-light`, `ink-dim`) |
| каталог | темы, которые объявляет провайдер; владелец каталога в графе — один |
| реестр | словарь владельца: токен → `root` или `mode`; по нему сборка проверяет полноту темы |

`extends` режима ссылается на режим той же темы: итоговые токены — предки по
цепочке, затем свои. `extensions` granum не интерпретирует: поле уезжает в
`virtual:granum/themes` как есть — так дизайн-система передаёт приложению,
например, пропы компонентов по умолчанию.

## Каталог и выбор темы

Каталог объявляет провайдер — обычно отдельный пакет токенов без компонентов
([авторам провайдеров](./authoring-providers.md#темы-каталог-реестр-данные)).
Приложение выбирает тему в конфиге:

```ts
export default defineGranumConfig({
  engine: windEngine(),
  providers: ['@acme/ui'],
  theme: 'ink',          // id каталога; '@acme/tokens:ink' — квалифицированный id
  previews: ['paper'],   // темы для показа рядом с активной
  modes: { names: ['light', 'dark', 'dim'] },
})
```

Без `theme` берётся `defaultTheme` владельца каталога (или единственная тема
каталога). Источник виден в отчёте и `doctor` как `themeSource`: `provider` —
id из конфига, `default` — тема по умолчанию владельца, `app` — тема-объект
приложения. Владельца не обязательно перечислять в `providers`: строковая
зависимость манифеста (`dependencies: ['@acme/tokens']`) подгружает донора от
каталога зависящего пакета, и его компоненты селекция `'all'` не выбирает.

Данные читаются только у активной темы и превью; остальные темы каталога в
сборку не попадают и не открываются. Неизвестный id — `ThemeResolutionError`
(`unknown-theme`) со списком доступных; два владельца каталога в графе —
`multiple-theme-owners`.

## Набор режимов и режимы приложения

Без `modes.names` в CSS едут режим по умолчанию темы (`light`) и ключи
`modes.define`: тема собирается под приложение, и второй режим — его решение, а не
умолчание. Нужен тёмный — назовите его: `modes: { names: ['light', 'dark'] }`. Режим
по умолчанию всегда первый; если `modes.names` его не называет, режимом по умолчанию
сборки становится первый из набора. Режим, от которого наследует режим набора
(`extends`), сам в набор входить не обязан: его значения берутся по цепочке, блока у
него нет. Имя вне темы и `define` — `unknown-mode`.

```ts
modes: {
  define: {
    ocean: { extends: 'dark', tokens: { 'th-accent': '#0ea5e9' }, title: 'Океан', colorScheme: 'dark' },
    sepia: { extends: 'light', tokensRef: new URL('./src/sepia.css', import.meta.url).href },
  },
  tokenOverrides: { root: { 'th-radius': '4px' }, dark: { 'th-bg': '#050505' } },
  strictTokens: true,
  system: 'media',
}
```

`define` — режим приложения поверх режима темы или другого `define`: берёт
итоговые значения базы (с токенами компонентов) и дописывает свои. Фолбэки
`@supports` база отдаёт посчитанными от своих значений; режиму, который меняет
роли, нужны свои — `fallbacks: [{ supports, tokens }]`, они встают после
унаследованных и перекрывают их по токену. Неизвестная
база и цикл — предупреждения `mode-extends-unresolved` и `mode-extends-cycle`,
такой режим наследует режим по умолчанию. Имя `define`, совпавшее с режимом
темы, — та же пара, ошибка `activation-collision`. `tokensRef` — CSS-файл
приложения с одним плоским блоком токенов; литеральные `tokens` важнее.

`tokenOverrides.root` ложится в режимонезависимые значения, `tokenOverrides.<режим>` —
в режим; режим вне набора — `unknown-mode`. При `strictTokens: true` override
токена, которого нет ни в данных темы, ни в токенах компонентов, отбрасывается, а
в отчёт попадает `override-skipped`. `system: 'media'` добавляет тёмный режим по
`prefers-color-scheme` для страницы, на которой атрибут ещё не выставлен.

## Активация

Режим включается атрибутом на корне: по умолчанию `data-theme="<тема>-<режим>"`.
Атрибут и шаблон значения меняются в `modes.activation`:

```ts
modes: { activation: { attribute: 'data-theme', value: '{theme}-{mode}' } }
```

Шаблон обязан содержать `{mode}`, а значения всех пар активной темы, `define` и
превью — различаться; иначе `activation-collision`. Классов `.light`/`.dark`
granum не выводит. Вариант `dark:` движка строится по парам режимов с
`colorScheme: 'dark'` (`[data-theme="ink-dark"] .dark\:…`): это потомковый
селектор, и светлый остров внутри тёмной страницы его тоже совпадает — для
островов служат токены режима, а не вариант.

## Слои значений

Значение токена в режиме собирается из слоёв, каждый следующий перекрывает:

1. данные темы — `root`, затем цепочка режима;
2. токены компонентов для активной темы — в порядке селекции;
3. тема-объект приложения;
4. `modes.define`;
5. `modes.tokenOverrides`.

Токен, объявленный хоть в одном режиме, получает значение в каждом: по цепочке
`extends` режима, иначе из режима по умолчанию. Такое значение — запасное: то,
что режиму уже дал другой слой, оно не перекрывает. Значение, взятое из режима по
умолчанию, приходит с его фолбэками `@supports` для этого токена — раньше своих
фолбэков режима. Одна функция считает значение
для CSS, отчёта и CLI: `granum tokens <id:Name> --deep` показывает цепочку слоёв по
каждому режиму вместе с темой и режимом, откуда пришло значение.

## Токены компонента по темам

Токены компонента лежат у компонента, в папке `themesDir`: `<тема>/root.json` и
`<тема>/modes/<режим>.json` (или `.css` с одним плоским блоком). Сборка провайдера
кладёт их в манифест. Для активной темы значение токена ищется так: режим, его
предки по `extends`, режим по умолчанию — и в каждом из них сначала тема, затем её
предки по каталогу. Так у темы `ink`, наследующей `paper`, режим `dim`
(наследует `dark`) берёт токен кнопки из `paper/modes/dark.json`, если у `ink` его нет.

Компонент вправе класть токены для тем чужого каталога — спутник для темы
дизайн-системы: они применяются, когда эта тема активна. Папка темы, которой нет
ни в одном каталоге графа, — предупреждение `component-theme-unknown`, а не ошибка.

## Раскладка CSS

```css
@layer granum.tokens {
  :root { --th-radius: 2px; }                        /* литералы root */
}
@layer granum.themes {
  :root, [data-theme] { --th-ring: 0 0 0 2px var(--th-accent); }
  :root, [data-theme="ink-light"] { color-scheme: light; --th-bg: #ffffff; }
  [data-theme="ink-dark"] { color-scheme: dark; --th-bg: #0f172a; }
  [data-theme="ink-dim"] { color-scheme: dark; --th-bg: #1e293b; }
  @supports not (color: color-mix(in oklab, red, red)) {
    :root:not([data-theme]), [data-theme="ink-light"] { … }
  }
  [data-theme="paper-light"], [data-theme="paper-dark"] { … }  /* превью: формулы */
  [data-theme="paper-light"] { … }                   /* превью: полный блок */
}
```

Формула со ссылкой `var(` — в `root` или одинаковая во всех режимах — стоит под
общей границей `:root, [data-theme]`: она пересчитывается на каждом острове
режима, а не наследуется готовой от корня. Режим по умолчанию идёт первым под
`:root` и своей парой, остальные — по порядку набора; при равной специфичности
решает позиция. Затем фолбэки `@supports` в том же порядке: фолбэк режима по
умолчанию — под `:root:not([data-theme])` и своей парой, а не под `:root`, иначе он
перебил бы позицией пару другого режима на корне. При `system: 'media'` список
замыкает блок `prefers-color-scheme`, и фолбэки тёмного режима лежат внутри того же
медиазапроса. `colorScheme` режима — объявление
`color-scheme` в его блоке. `baseCss` данных темы уходит в слой `base`.

## Превью

`previews` показывают другие темы каталога рядом с активной — на странице
дизайн-системы или портала. Каждая пара превью получает полный блок: свои
литералы `root`, режим, токены компонентов селекции и фолбэки; формулы — один раз
под списком её пар (`[data-theme="paper-light"], [data-theme="paper-dark"]`).
Префикс значения совпал бы и с парами активной темы (`slate-` — с
`slate-hc-light`). Под `:root` превью не выходит
никогда, и обрезка токенов режет её так же, как активную тему.

По умолчанию блоки превью лежат в общем листе, и их платит каждая страница.
`css: { previews: 'separate' }` убирает их оттуда в модули
`virtual:granum/previews.css` (все темы превью) и `virtual:granum/previews/<id>.css`
(одна) — их импортирует только страница, которая превью показывает:

```ts
// src/pages/themes/[slug].astro — и больше нигде
import 'virtual:granum/previews.css'
```

Модуль превью несёт объявление порядка слоёв и кладёт блоки в слой `themes`,
поэтому каскад тот же, что при общем листе.

## Своя тема приложения

`theme` принимает и объект `GranumThemeData` — полные данные. Наследование
от темы каталога приложение разрешает само, до конфига, а `extends` говорит
granum, чьи токены компонентов брать за основу:

```ts
theme: {
  ...brandData,          // полные данные: id, title, root, modes
  extends: 'paper',      // токены компонентов для режимов, где тема их не задала
  sources: ['src/theme'],
}
```

Тема-объект идёт слоем после токенов компонентов: значение токена кнопки в её
режиме перекрывает токен компонента. `sources` — файлы, из которых тема собрана:
конфиг читается один раз на процесс Vite, поэтому их правка в dev перезапускает
сервер. Стенд — `apps/app-theme-own`.

## Потребление и отчёт

Сборка провайдера записывает в манифест, какие токены компонент
**потребляет** (`var(--x)` в CSS и JS, литералы `'--x'` в JS, `dynamicTokens`)
и какие из них **требует извне**: потребление без fallback минус то, что
компонент присваивает сам (`--x:` в своём CSS, переменные `v-bind()` из
`<style>`). Приложение объединяет потребление с `appSources` — это корни
обрезки. `token-undefined` в отчёте и в `doctor` — одно множество: токен,
который выбранный компонент требует извне (кроме `dynamicTokens`) и который не
получил значения ни в одном режиме активной темы и не объявлен инлайнимыми
файлами. Токены разметки самого приложения в него не входят.

Токен, который компонент читает **только** через `var(--x, запасное)`, извне не
требуется, но и молчать о нём опасно: если его не задаёт ни один слой, компонент
всегда рисует запасное значение, и переименованный токен этим и прячется. Сборка
записывает такие токены в манифест отдельно, а `doctor` называет незаданные
находкой `token-fallback-only`. Намеренный хук — значение по умолчанию, которое
тема или приложение вправе переопределить, — компонент объявляет в `hookTokens`.

## Обрезка токенов

```ts
pruneTokens: { mode: 'on', keep: ['th-brand-*'] }
```

Обрезка удаляет из слоёв `tokens` и `themes` объявления, недостижимые от
корней; `base` не трогается. Данные темы и токены компонентов — пакетный слой и
режутся по достижимости. Корни: потребление в CSS компонентов селекции и в
выводе движка, `consumes` и `dynamic` из манифестов, `appSources`, значения
приложения (`modes.define`, `modes.tokenOverrides`, тема-объект), `keep`.
Достижимость идёт по графу «токен → токены в его значении», поэтому
`--soft: color-mix(…, var(--danger))` держит `--danger`. Токен, нужный одному
режиму, сохраняется во всех.

Порядок внедрения: `mode: 'report'` → посмотреть план в отчёте или
`granum prune` → `mode: 'on'`. Режим `off` не меняет эмиссию ни на байт.
Стенд [`bench-pruned`](./measuring-weight.md) показывает эффект.

## Рантайм

```ts
import { createThemeController } from '@feugene/granum/runtime'
import manifest from 'virtual:granum/themes'

const themes = createThemeController(manifest)
themes.theme              // { id: 'ink', title: 'Чернила' } — только чтение
themes.modes()            // [{ name: 'light', value: 'ink-light', colorScheme: 'light' }, …]
themes.setMode('dim')     // <html data-theme="ink-dim">
themes.mode               // 'dim'
```

Манифест — активная тема, её режимы с парами в порядке CSS, режим по умолчанию,
атрибут активации и `extensions`; от селекции компонентов он не зависит.
Контроллер хранит имя **режима**, а не пару (ключ `granum-theme`): смена темы на
сборке не сбрасывает выбор пользователя. На старте `initial: 'auto'` берёт пару,
уже выставленную на корне, — тогда корень не трогается; иначе сохранённый режим,
системную схему (первый режим с подходящим `colorScheme`) и режим по умолчанию.
Пару до первого кадра ставит `createThemeScript` или опция плагина
`themeScript` ([серверный рендер](./ssr.md)).
