# Движки и диалекты

> 🇬🇧 English version: [`../en/engines-and-dialects.md`](../en/engines-and-dialects.md).

Движок утилит в granum не встроен: ядро отдаёт контракт `GranumEngine` и
хелперы, а реализацию приложение выбирает само и передаёт инстансом. Эта
страница — зачем так, как поставить движок, чем диалект отличается от отпечатка
словаря и что делать, когда они расходятся.

## Почему движок выбирает приложение

Правило утилиты — функция против контракта конкретного генератора: своя
семантика вариантов, своё чтение темы, свой разбор произвольных значений.
Сложить правила двух генераторов в один слой `utilities` нельзя: класс получил
бы два вердикта, а «последнее совпавшее побеждает» потеряло бы смысл. Значит
генератор в сборке один — и выбирает его тот, кто отвечает за результат, то
есть приложение.

Отсюда всё остальное: `engine` в `granum.config.*` обязателен и принимает
инстанс, а строка `'builtin'` и объект опций не принимаются
(`InvalidConfigError` с путём до поля). Сборка провайдера тоже требует явный
инстанс: список классов в манифесте — факт о конкретной реализации, а не о
пакете.

## Установка и настройка

Реализация по умолчанию — `@feugene/granum-engine-mini`: вендоренный форк ядра
UnoCSS 66.7.5 с `preset-mini` и доп-правилами, ноль зависимостей.

```bash
yarn add -D @feugene/granum @feugene/granum-engine-mini
```

```ts
// granum.config.ts
import { defineGranumConfig } from '@feugene/granum/vite'
import { miniEngine } from '@feugene/granum-engine-mini'

export default defineGranumConfig({
  engine: miniEngine(),
  providers: ['@acme/ui'],
  appSources: { dirs: ['src'] },
})
```

| Опция `miniEngine` | По умолчанию | Меняет диалект | Меняет отпечаток |
|---|---|---|---|
| `extraRules` | `true` | да | да |
| `rules`, `variants` | — | нет | да |
| `preflights` | — | нет | нет |
| `preflight` | `true` | нет | нет |
| `variablePrefix` | `--un-` | нет | нет |

Опция, меняющая набор генерируемых имён качественно, обязана менять диалект:
`extraRules: false` выключает `divide-y`, `space-x-4` и `tabular-nums`, и это
уже другой словарь — `unocss/preset-mini@66` вместо
`unocss/preset-mini+granum@66`. Опция, меняющая только вывод, диалект не
меняет.

## Своё правило приложению

Правила приложения передаются фабрике движка, а не конфигу granum: у конфига
поля для правил нет и не появится.

```ts
engine: miniEngine({ rules: [['x-app-only', { 'outline-style': 'dotted' }]] }),
```

Диалект при этом тот же — словарь preset-mini никуда не делся, — а отпечаток
другой: движок знает имя, которого не знала сборка пакетов. Что из этого
следует, ниже.

## Диалект и отпечаток

Две сущности, а не одна, потому что у них разные потребители и разные решения.

### Диалект — имя словаря

`<vendor>/<vocabulary>@<major>`: `unocss/preset-mini+granum@66`,
`granum-fixtures/atoms@1`. Сравнивается строгим равенством строк; мажор в конце
— часть имени, а не диапазон, потому что `@66` и `@67` — разные словари, а не
версии одного.

Диалектом управляется ровно одно решение: **грузить ли модуль правил
провайдера.** Правило, написанное для словаря, переживает смену реализации
внутри мажора: `atom-stack` ничего не знает о `divide-y`, появившемся в новом
миноре апстрима, и не ломается от него.

### Отпечаток — ключ фактического набора имён

`vocabulary` — непрозрачная строка, меняющаяся ровно тогда, когда меняется
множество имён, которые движок умеет сгенерировать. Ядро считает её хелпером
`vocabularyFingerprint({ rules, variants })` из `@feugene/granum/engine`: по
идентификаторам правил и именам вариантов, независимо от их порядка.

Отпечатком управляется другое решение: **верить ли списку классов в манифесте
пакета.** Список отфильтрован движком сборки пакета — класс без правила в
манифест не попадает, — поэтому реализация, знающая больше имён, нашла бы в тех
же файлах больше классов. Диалект этого не видит по определению: внутри одного
мажора набор имён не постоянен, апстрим добавляет правила в минорах, а
приложение — свои правила фабрике.

## Таблица решений

| Диалект манифеста | Отпечаток | Что делает granum | Что видит разработчик |
|---|---|---|---|
| `null` | `null` | быстрый путь, пересчёта нет | ничего: пакет ни от какого словаря не зависит |
| равен | равен | классы из манифеста, правила пакета загружены | ничего, это норма |
| равен | другой | пересчёт с правилами пакета | `reason: 'vocabulary'` у провайдера в отчёте; при разнице наборов — `provider-classes-recovered` / `provider-classes-dropped` |
| другой | — | пересчёт без правил пакета | `provider-dialect-mismatch`; плюс `engine-rules-skipped`, если пакет привёз модуль правил; при разнице наборов — те же коды |

Пересчёт — не догадка: классы каждого компонента извлекаются заново из его
`files`, перечисленных в манифесте, движком приложения, и результат сверяется
со списком манифеста. Разница называется:

- **`gained`** — классы, которые сборка пакета потеряла, потому что её движок
  этих имён не знал, а движок приложения знает: они возвращаются в сборку;
- **`lost`** — классы из манифеста, для которых у движка приложения нет
  правила: они остаются во входе движка и видны в `unmatched` отчёта. Пересчёт
  не имеет права сделать потерю тише, чем она была.

`safelist` пересчёту не подлежит: это авторское объявление, а не производная;
запись без правила попадает в `safelist-dead`, как и раньше. Результат
пересчёта кэшируется в памяти процесса, на диск он не пишется.

Расхождение отпечатков само по себе — не предупреждение: так выглядит любое
приложение со своим правилом в фабрике. Предупреждает разница наборов.

## `provider-dialect-mismatch`

Пакет собран движком другого словаря. Следствия по порядку:

1. модуль правил пакета не загружен (`engine-rules-skipped`): правило чужого
   словаря исполнять нельзя;
2. классы пакета пересчитаны — без его правил;
3. имена, которых словарь приложения не знает, названы в `lost` и видны в
   `unmatched`.

Что делать: либо взять движок диалекта пакета, либо добавить нужные правила
фабрике своего (`miniEngine({ rules: […] })`). Смешать два словаря в одной
сборке нельзя, и это не ограничение реализации: имена словарей пересекаются, а
смысл у них разный, и класс `.p-4` получил бы два вердикта в одном слое.

## `provider-classes-dropped`

Класс из манифеста пакета не покрасился: правила для него у движка приложения
нет. Причина ищется одной командой (см. [CLI](./cli.md)):

```bash
granum why-css granum.config.ts divide-y
```

Она назовёт, из какого пакета класс, каким движком и для какого словаря тот
собран, загружены ли его правила, и предложит два выхода — движок того же
диалекта или своё правило в фабрике. Обратный код,
`provider-classes-recovered`, означает, что классы потеряла сборка пакета, а
приложение их вернуло: это дефект на стороне пакета и чинится он там.

## Свой движок

Интерфейс из `@feugene/granum/engine` небольшой:

```ts
interface GranumEngine {
  readonly name: string
  readonly version?: string
  readonly dialect: string
  readonly vocabulary: string
  extract: (code: string, id: string) => ReadonlySet<string>
  generate: (input: EngineInput) => Promise<EngineOutput>
}
```

Обязанности реализации:

- **чистота и детерминизм**: без FS, сети и глобального состояния между
  вызовами, вывод не зависит от порядка классов на входе;
- **ни одного молчащего класса**: каждое имя входа попадает либо в `matched`
  (с правилом, источником и слоем), либо в `unmatched`;
- **порядок правил**: встроенные < правила провайдеров в порядке графа <
  правила приложения, при совпадении матчеров побеждает последнее совпавшее;
- **честный отпечаток**: `vocabulary` меняется всякий раз, когда меняется
  множество имён — считайте его `vocabularyFingerprint` либо гарантируйте это
  правило сами.

Хелперы ядра `extractClasses`, `parseDialect` и `vocabularyFingerprint`
предназначены именно авторам движков; реализации в ядре нет вовсе. Рабочий
пример с нуля, без единой строчки UnoCSS, — `fixtures/atoms-engine` в этом
репозитории: словарь из шести правил, свой диалект `granum-fixtures/atoms@1`, и
на нём собираются фикстура `atoms-package` и приложение `apps/app-atoms`.

## Версия реализации ни на что не влияет

`version` уезжает в манифест и печатается диагностикой, но в решениях не
участвует: ни сравнением, ни диапазоном. Патч, не добавивший правил, не должен
стоить приложению пересчёта всех пакетов, а минор, добавивший их, — должен;
различает эти два случая отпечаток, а не номер. Два инстанса с разными
версиями и одним отпечатком идут быстрым путём.
