# Документация `@feugene/granum`

> Статус: **реализовано**, версия 0.1.0; этапы 0–7 плана выполнены 2026-09-25.
> Преемник `@feugene/unocss-preset-granular` (далее — «пресет v1», не изменяется).

Granum — конвейер сборки гранулярных UI-пакетов: JS/Vue-компоненты, их стили,
дизайн-токены и темы проходят один путь от исходников провайдера до дистрибутива
приложения. Оркестратор — собственный Vite-плагин, а не конфиг UnoCSS; движок
утилит — сменный адаптер внутри CSS-канала.

Визуальная схема (сейчас / цель, блоки, ожидаемый результат):
https://claude.ai/artifact/41CJUc18uAaaCdm23xWezq (исходник: [`architecture-pipeline.html`](./architecture-pipeline.html))

## Документы

| Файл | Что в нём | Читать когда |
|---|---|---|
| [`spec.md`](./spec.md) | Техническое задание: цели, границы, архитектура, требования по блокам с идентификаторами, ошибки, критерии приёмки | перед любой задачей по реализации |
| [`invariants.md`](./invariants.md) | Реестр инвариантов `INV-*`: что обязано быть верным всегда, кто это гарантирует и как проверяется | при проектировании модуля, при написании теста, при ревью |
| [`manifest.md`](./manifest.md) | Формат `granum.manifest.json`: поля, правила валидации, пример | реализация `/build` и `/vite`, диагностика |
| [`decisions.md`](./decisions.md) | Архитектурные решения `ADR-*` с выбранным вариантом и последствиями | когда кажется, что «можно было иначе» |
| [`plan.md`](./plan.md) | План реализации: этапы, задачи, определение готовности, риски | планирование работ, оценка прогресса |
| [`architecture-pipeline.html`](./architecture-pipeline.html) | Исходник визуальной схемы конвейера (та же страница, что опубликована по ссылке выше) | когда нужна картинка, а не текст |

## Порядок чтения

1. `spec.md` §1–§4 — зачем и из чего состоит.
2. `invariants.md` — целиком, один раз.
3. `decisions.md` — чтобы не переоткрывать закрытые вопросы.
4. `plan.md` — с какого этапа начинать.
5. Остальные разделы `spec.md` и `manifest.md` — по мере работы над блоком.

## Соглашения

- Идентификаторы требований: `C-*` контракт, `B-*` сборка провайдера, `M-*` манифест,
  `R-*` резолвер, `E-*` движок, `A-*` плагин приложения, `T-*` токены и темы,
  `RT-*` рантайм, `D-*` диагностика, `N-*` нефункциональные. Инварианты — `INV-*`,
  решения — `ADR-*`.
- Слова **MUST / MUST NOT / SHOULD / MAY** — по RFC 2119.
- Язык документации — русский; идентификаторы, имена полей и сообщения ошибок —
  английские.
- Ссылки на пресет v1 даются как «SPEC v1 §N» и указывают на
  `packages/unocss-preset-granular/docs/SPEC.md` репозитория `unocss-preset-granular`.
