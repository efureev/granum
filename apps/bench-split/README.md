# `bench-split`

Стенд опции `css.split` — отдельный ассет на каждый слой каскада (A-21).

Набор намеренно совпадает с [`bench-one`](../bench-one/README.md): тот же
компонент `XhPanel`, тот же фундамент, те же две темы. Отличие ровно одно —
`css.split: true`, — поэтому разницу в дистрибутиве можно приписать опции, а не
составу.

## Зачем это нужно

Один файл жмётся лучше: общий словарь сжатия на весь CSS. Но инвалидируется он
целиком — правка разметки приложения сбрасывает кеш токенов и тем, которые не
менялись. На дизайн-системе токены с темами — это десятки килобайт, которые
браузер вынужден качать заново из-за одной изменённой утилиты.

При `split` каждый непустой слой уезжает своим ассетом с собственным хешем:

```
dist/assets/index-*.css                 объявление порядка слоёв (одна строка)
dist/assets/granum.tokens-*.css         @layer granum.tokens { … }
dist/assets/granum.base-*.css           @layer granum.base { … }
dist/assets/granum.themes-*.css         @layer granum.themes { … }
dist/assets/granum.components-*.css     @layer granum.components { … }
dist/assets/granum.utilities-*.css      @layer granum.utilities { … }
```

`<link>` на них проставляются в `index.html` **в порядке слоёв**: первое
появление слоя задаёт его место в каскаде, поэтому порядок ссылок и есть порядок
каскада. Объявление `@layer …;` одно и приходит раньше слоёв — ссылку на ассет
входа Vite ставит первой.

## Что проверяет `yarn verify`

`scripts/verify-split.mjs` делает то, чего одной сборкой не проверить: собирает
стенд, **правит класс в `App.vue`**, собирает снова и сравнивает имена ассетов.

Ожидание: изменился ровно один ассет из пяти — тот, что несёт `utilities`.
Остальные четыре сохранили имена, то есть и содержимое: браузер их не перекачает.
Затем `App.vue` возвращается на место, и проверяется, что имена вернулись к
исходным — заодно это проверка детерминированности сборки.

Плюс структурные утверждения: ассет только у непустого слоя, ни один ассет не
содержит чужого слоя, объявление порядка ровно одно и не продублировано в слоях,
конкатенация ассетов в порядке слоёв равна тому, что отдал бы один файл.

## Чего стенд не проверяет

Сжатый вес. Пять файлов суммарно жмутся хуже одного — это цена опции, а не
дефект, и мерить её должен `sizes`, а не гейт. Смысл `split` в том, что
перекачивается не весь CSS, а один слой; сумма при холодном кеше при этом
немного больше.

Замер на настоящем приложении (витрина granularity, восемь провайдеров, 116
компонентов): сумма слоёв 39.3 kB gzip против 38.5 kB одним файлом — плата 855
байт, +2.2%. Взамен правка разметки перекачивает 20.9 kB вместо 38.5, правка
темы — 6.0 kB вместо 38.5. Стоит ли оно того — решает приложение: чем чаще
меняется разметка и реже фундамент, тем выгоднее.

```bash
yarn workspace @granum-apps/bench-split build
yarn workspace @granum-apps/bench-split verify
```
