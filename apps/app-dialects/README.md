# `app-dialects`

Стенд ветки **«другой диалект»** из таблицы решений §8
[ТЗ движка](../../docs/spec-engine.md).

Пакет `@granum-fixtures/atoms` собран движком словаря `granum-fixtures/atoms@1`:
у него своя вселенная имён (`atom-stack`, `atom-gap-2`, `atom-bg-[…]`), и правила
для них пакет привозит модулем. Приложение берёт `windEngine()`, то есть словарь
`unocss/preset-wind3+granum@66`, где ни одного `atom-*` нет.

Что обязано произойти:

1. правила пакета не загружаются вовсе — правило, написанное для чужого словаря,
   в этой сборке значило бы не то, что значило у автора (`engine-rules-skipped`);
2. granum не верит списку классов манифеста и пересчитывает его своим движком;
3. ни одно имя не исчезает молча: все семь названы в `lost` отчёта, поданы
   движку и видны в `unmatched` с источником `@granum-fixtures/atoms`;
4. фундамент пакета при этом доезжает целиком — токены и тема это CSS-файлы, от
   словаря утилит они не зависят;
5. доктор говорит об этом тремя предупреждениями: `provider-dialect-mismatch`,
   `engine-rules-skipped`, `provider-classes-dropped` (последнее — с перечислением
   имён).

Пересчёт идёт по пакету целиком, поэтому в `lost` попадают и классы `AtChip`,
которого в селекции нет.

Починка для разработчика ровно одна из двух: поставить движок диалекта пакета
либо добавить нужные правила в фабрику своего. Именно это и печатает
`granum why-css granum.config.ts atom-stack`.

Обратная сторона той же монеты — [`app-atoms`](../app-atoms/README.md): там
движок приложения и пакет говорят на одном словаре, и пересчёта нет.
