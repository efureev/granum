# `app-components`

Стенд канала JS: `virtual:granum/components` на настоящей сборке (A-5, INV-JS-1).

Пакет — `@granum-fixtures/mini-ds`, тот же, что у [`dist-audit`](../dist-audit/README.md).
Отличие одно и оно принципиальное: там компонент импортируется из бареля пакета, а
здесь — из виртуального модуля, который granum собирает по селекции.

## Что проверяется

В селекции **оба** компонента, в разметке импортирован **один**:

```ts
import { XxCard } from 'virtual:granum/components'
```

Отсюда два утверждения, которые больше проверить негде:

1. **В бандле один компонент из двух.** Модуль состоит из реэкспортов и не имеет
   побочных эффектов, поэтому `XxBadge` вырезает tree-shaking. В `dist/assets/pkg-*.js`
   остаётся только `XxCard` — ни имени второго компонента, ни его классов.
2. **CSS при этом содержит оба.** CSS идёт по селекции, JS — по импортам; это разные
   каналы, и стенд фиксирует разницу. `inline-block` и `bg-[var(--xxx-accent)]` в
   дистрибутиве есть, хотя кода бейджа там нет, — и `granum audit` на стенде чист,
   потому что селекцию никто не сужал.

До этого стенда форма виртуального модуля жила только в юните на программной сборке:
ни одно приложение репозитория его не импортировало.

## Чего стенд не проверяет

Guard импортов (A-6): в селекции оба компонента, запрещать нечего. Обрезка токенов
выключена — предмет стенда JS, и лишняя машинерия между утверждением и фактом здесь
ни к чему.

Типы виртуальных модулей пакет не поставляет, поэтому объявления лежат локально в
[`src/granum.d.ts`](src/granum.d.ts).

```bash
yarn workspace @granum-apps/app-components build
yarn workspace @granum-apps/app-components verify
```
