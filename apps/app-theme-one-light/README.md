# `app-theme-one-light`

Один компонент, одна тема, один режим — из дизайн-системы, у которой тема несёт значения
**всех** её компонентов (ADR-13). Кнопка `VdButton` из
[`@granum-fixtures/valued-ds`](../../fixtures/valued-ds-package/README.md), тема «Камень» (`stone`),
режим `light`, обрезка токенов включена (`pruneTokens: { mode: 'on' }`, T-2, T-14). Пара —
[`app-theme-one-dark`](../app-theme-one-dark/README.md): тот же набор в тёмном режиме.

```bash
yarn workspace @granum-apps/app-theme-one-light build
yarn workspace @granum-apps/app-theme-one-light verify
```

## Что держит стенд

В слоях `tokens` и `themes` собранного CSS — **ровно** токены, которые читает кнопка, и токены, на
которые они ссылаются, со значениями «Камня» в своём режиме:

| Токен | `light` | `dark` |
| --- | --- | --- |
| `--vd-button-bg` → `--vd-accent` | `#57534e` | `#d6d3d1` |
| `--vd-button-fg` → `--vd-accent-fg` | `#fff` | `#1c1917` |
| `--vd-button-radius` → `--vd-radius` | `6px` | `6px` |

Тема несёт и значения карточки и группы, и роли страницы (`--vd-bg`, `--vd-fg`, `--vd-font`) —
обрезка их снимает: кнопка их не читает. Других тем каталога в сборке нет.

**Режимы друг в друга не протекают.** Во всём CSS сборки нет пары, `color-scheme` и значений другого
режима — ни под токенами кнопки, ни под каким другим именем: значения, уникальные для другого режима,
ищутся сами по себе.

Проверка — точный состав, а не поиск подстрок: ожидания пары (`../shared/theme-one.mjs`)
перечисляют каждый блок со слоем и селектором и каждый токен, и лишний токен, как и токен не под тем
селектором, роняет `verify`. Служебные переменные lightningcss для `color-scheme`
(`--lightningcss-*`) — не токены дизайн-системы, они исключены явно.
